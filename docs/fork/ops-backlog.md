# Дефекты эксплуатации

Собрано на рабочем сервере 2.26.192.83 (Ubuntu 20.04, панель 0.3.0, инстанс 10)
27 октября 2026.

## 1. Статистика трафика не пишется 17 дней

`traffic_events`: 941 941 строка, последняя запись `2026-10-10T02:36:22Z`.
Все строки принадлежат `instance_id=1`, которого уже нет: текущий инстанс 10
создан 12 октября. Файл базы 405 МБ, из них 262 МБ таблица и 141 МБ индекс.

При этом `sessions` и `audit_log` обновляются (последняя запись 08:00 сегодня),
то есть панель жива, не работает именно инжест журнала инстанса.

Следствия: квоты и расход в UI не считаются, база растет без ретеншена.

## 2. Журналы занимают 3.7 ГБ

- `/var/log/journal` - 3.0 ГБ, `SystemMaxUse` не задан, journald уперся в
  дефолтные 10 процентов файловой системы.
- `/var/log/syslog` и архивы - около 0.5 ГБ, 23 863 строки olcrtc в текущем
  файле за неполные сутки, потому что у инстанса `debug: true`.
- `btmp` - 65 МБ, 66 217 неудачных попыток SSH.

Диск: 22 ГБ из 30 занято, свободно 6.5 ГБ.

## 3. Обновления релизов занимают 653 МБ

`/var/lib/olcrtc-panel/releases` содержит 15 бандлов, нужны только `current` и
`previous`.

## 4. TLS не годится для клиентов

Панель отдает самоподписанный сертификат локального CA
(`CN = olcrtc-panel local CA`). Приложения, которые проверяют цепочку, не могут
загрузить подписку: в журнале каждые 30 минут
`TLS handshake error ... unknown certificate` с адреса 95.68.226.60.

Нужен домен и ACME (acme.sh на сервере уже установлен) либо явная раздача
корневого сертификата клиентам.

## 5. Сетевая гигиена

- `listen: 0.0.0.0:62593`, `ufw` выключен.
- SSH: root по паролю, 66 тысяч попыток подбора, fail2ban банит (8040 банов).
- Ubuntu 20.04 вне стандартной поддержки.

## 6. Дефолты liveness жестче, чем в ядре

В форме инстанса `10s / 5s / 3`, в документации ядра `10s / 15s / 4`. Из-за
этого живая сессия закрывалась по таймауту при RTT 9.5 с.

## 7. Наблюдаемость отсутствует

Статус инстанса в UI - это `systemctl is-active`. Мертвая smux-сессия при живом
WebRTC показывает "работает", хотя трафика нет. Нужен health по контрольному
пингу, а не по состоянию юнита.

## План

1. Выпилить WB-стек и автообновление с мертвого канала.
2. Ретеншен `traffic_events` (агрегаты в `traffic_counters`, удаление старых
   строк, VACUUM) и починить инжест.
3. `debug` по умолчанию выключен, лимиты journald, ротация syslog.
4. TLS: домен и ACME либо документированная раздача CA.
5. Health по сессии, алерт при мертвом туннеле.
6. Дефолты liveness привести к 15 с и 4 попыткам.
7. Сеть: bind на localhost за реверс-прокси либо ufw.

Критерий приемки: на сервере `df` не растет за неделю, статистика трафика
обновляется, подписка грузится без warning о сертификате, в UI видно мертвый
туннель.
